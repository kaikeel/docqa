# Kaikeel Handbook Lite: Warranty Policy

*Fictional sample document for the DocQA demo.*

## Warranty period

Every fixed-price project includes a **7-day warranty**. The warranty period starts on the
day the client confirms receipt of the handover package and ends seven calendar days later.

## What the warranty covers

During the warranty period we fix, free of charge, any defect where the delivered software
does not behave as described in the agreed acceptance criteria. Typical examples:

- a documented command fails on a supported platform;
- an API endpoint returns the wrong status code or response shape;
- a test in the delivered test suite fails on a clean checkout.

## What the warranty does not cover

- New features or changes to the agreed scope. These are handled as a change request with
  a separate estimate.
- Problems caused by changes the client made to the code or infrastructure after handover.
- Outages of third-party services, such as a payment provider or a hosted model API.
- Hosting costs, API usage fees or licence fees for third-party software.

## How to report a defect

The client reports a defect by replying to the handover thread with: the steps to
reproduce, the expected result, the actual result, and any error message. We acknowledge
every report within one business day.

## Fix timeline

Critical defects that block the main workflow are fixed within two business days. Other
defects are fixed within five business days. If a fix lands after the warranty period ends
but the report arrived inside it, the fix is still free.
